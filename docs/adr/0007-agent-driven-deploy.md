# ADR-0007: Agent-driven deployment

The password setup and browser handoff are superseded by [ADR-0010](0010-browser-password-authentication.md). Agent-guided deployment remains supported without requiring a one-time login link. The channel ordering — the runbook as the primary deployment channel — is superseded by [ADR-0012](0012-deploy-button-primary.md); the runbook remains the agent-guided channel.

The Deploy-to-Cloudflare button only covered `wrangler deploy`; everything that makes a deployment usable — a reachable hostname, the secrets, the first machine, browser sign-in, a model key — still happened in a terminal afterwards. And the button's default address is unusable in mainland China (`*.workers.dev` is blocked there), which the button flow could not fix without dashboard work. We decided the primary deployment channel is a runbook the owner's own coding agent executes: the owner hands their agent one paragraph pointing at `docs/agent-deploy.md`, and the agent deploys, verifies, sets up the secrets, and guides the steps that must stay human. Initialization follows ADR-0003's design: the agent generates and sets SERVER_KEY (and optionally MODEL_KEY), then verifies the owner API with it.

- **The runbook is the first-experience surface**: a versioned file in the repository, read by the owner's agent from source rather than pasted from a chat. Written as numbered steps with per-step verification and stop points — executable by heterogeneous agents (pi, Claude Code, …), not prose for humans. Its failure playbook absorbs the diagnosis paths the pilot deployment actually hit (name collisions, resident-isolate code lag, rejected model keys, secret-setting mistakes).
- **Default address is workers.dev** under a collision-safe unique worker name (`npm run deploy -- --name <name>`; workers.dev names are global, so a collision-safe unique name avoids the repository default). Custom domains drop out of the mainline into the runbook's appendix, attached only when workers.dev is unreachable or the owner wants one.
- **Secret discipline is part of the channel's contract**: secrets may be orchestrated by the agent but never observed by it — no key in prompts, tool arguments, or echoed output. SERVER_KEY is generated by a command the agent runs (`openssl rand -hex 32`, piped straight into `wrangler secret put`) and handed to the owner out of band; the model key's channel is the workspace's Settings page (or a command the owner runs).
- **The owner's part is one paragraph and the first message**: the agent runs the runbook, verifies the gates, and hands over a working workspace (a one-time login link minted through the owner API).
- The Deploy button stays as the no-agent alternative, unchanged; ADR-0003's SERVER_KEY design is untouched — how a deployment came to exist is orthogonal to who owns it.

Consequences: the repository must be public and the connector published to npm for the runbook to be executable as written (the open-source blockers); the runbook needs re-validation whenever the flow it describes changes — treat it as code, not documentation.
