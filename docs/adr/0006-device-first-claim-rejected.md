# ADR-0006: Device-first claiming and sign-in, no deploy-time secrets (rejected)

Status: **rejected** at the PR #60/#61 merge. ADR-0003 (the SERVER_KEY owner API) is the merged design: SERVER_KEY stays the deploy-time secret and the owner credential, `POST /api/login-link` mints browser sign-in links, and machines pair with one-time codes from `POST /api/pairing`. What survives from this ADR is the browser sign-in shape — a one-time link opening a session — and the demand that the fresh-deployment walk be executable by the owner's agent (ADR-0007). The text below is kept as the record of the rejected alternative.

A Deploy-to-Cloudflare deployment could not ask its owner to generate and keep three secrets (SERVER_KEY, OWNER_KEY/Access values) — the worst step was copying a pairing code out of a build log. We decided the deployment itself owns its trust: the Durable Object generates its signing secret on first boot, and the owner's authority is the Cloudflare account, proved once at claim time through Cloudflare's own API. The web workspace has no password and no input on its public pages; every browser session starts from a one-time link minted on an already-paired machine.

- **Claim (first machine):** `shepherd connect <url>` (no code) runs Wrangler's OAuth (`account:read`, `workers_scripts:write`), resolves the exact Worker behind the URL, writes a random `SHEPHERD_CLAIM_SECRET` through the Cloudflare API, and POSTs its SHA-256 to `/pair`. The Worker hashes its own secret and compares — a match proves the caller just wrote it through Cloudflare, which only someone managing this account can. Redeeming is once-only and marks the deployment claimed; later claims are refused. *Rejected:* first-connect-wins claiming (an unauthenticated public race for ownership), a pairing code printed in the build log (the UX this ADR removes), Cloudflare Access in front (ADR-0003's answer: needs a Zero Trust plan, three post-deploy settings, and blocks WebSocket at the Worker level).
- **Browser sign-in:** `/app` without a session is a page with no input that says the one way in — `shepherd login` on a paired machine prints a one-time link (single use, minutes of validity; the Feishu-era `openLink` machinery). A lost fleet re-claims on a new machine with the same Cloudflare authorization; a stolen deployment is recoverable only by whoever manages the account.
- **Keys:** the Durable Object's auth root (generated at first boot, in its own storage) signs everything SERVER_KEY used to; a still-set deploy-time SERVER_KEY stays in the verification set so pre-upgrade tokens, sessions and sealed secrets keep working. MODEL_KEY remains the only optional deploy-form secret.
- **The deploy form carries nothing.** `scripts/deploy.mjs` wraps `wrangler deploy`, stamps `SHEPHERD_IDENTITY` (account id + script name) for target checks, and prints the connect command.

Consequences: an unauthorized person knowing the URL can do nothing (no input, no code to guess, the claim secret must come through Cloudflare's API); the price is one Wrangler OAuth with `workers_scripts:write` — broader than this Worker alone, named plainly on the consent screen — and browser sign-in requires a paired machine at hand. Supersedes ADR-0003 decision 2 (Access front door) and its three post-deploy settings; decisions 3–8 stand.
