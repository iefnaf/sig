# ADR-0005: Agent-driven deployment

The Deploy-to-Cloudflare button only covered `wrangler deploy`; everything that makes a deployment usable — a reachable hostname, the first machine, browser sign-in, a model key — still happened in a terminal afterwards. And the button's default address is unusable in mainland China (`*.workers.dev` is blocked there), which the button flow could not fix without dashboard work. We decided the primary deployment channel is a runbook the owner's own coding agent executes: the owner hands their agent one paragraph pointing at `docs/agent-deploy.md`, and the agent deploys, verifies, claims, and guides the steps that must stay human.

- **The runbook is the first-experience surface**: a versioned file in the repository, read by the owner's agent from source rather than pasted from a chat. Written as numbered steps with per-step verification and stop points — executable by heterogeneous agents (pi, Claude Code, …), not prose for humans. Its failure playbook absorbs the diagnosis paths the pilot deployment actually hit (name collisions, resident-isolate code lag, rejected model keys, already-claimed resets).
- **Default address is workers.dev** under a collision-safe unique worker name (`npm run deploy -- --name <name>`; the script stamps the claim identity under that name). Custom domains drop out of the mainline into the runbook's appendix, attached only when workers.dev is unreachable or the owner wants one.
- **Secret discipline is part of the channel's contract**: secrets may be orchestrated by the agent but never observed by it — no key in prompts, tool arguments, or echoed output. The model key's channel is the workspace's Settings page (or a command the owner runs); the claim's channel is Cloudflare's OAuth. Same principle as ADR-0004's "the deployment owns its keys", extended to the deployer.
- **The owner's two clicks are the design, not a cost**: the Wrangler OAuth consent (serving deploy and claim at once) and the first message. Browser sign-in needs no click at all — the agent opens the one-time link.
- The Deploy button stays as the no-agent alternative, unchanged; ADR-0004's claim and sign-in design is untouched — how a deployment came to exist is orthogonal to who owns it.

Consequences: the repository must be public and the connector published to npm for the runbook to be executable as written (the open-source blockers); the runbook needs re-validation whenever the flow it describes changes — treat it as code, not documentation.
