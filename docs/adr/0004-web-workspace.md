# ADR-0004: The Sig web workspace

Status: accepted (2026-10-17; renumbered and adapted when ADR-0002/0003 took the Sig brand and the owner API). Amends ADR-0001 decisions 4, 7 and 12, which limited the web to companion pages, chat-only intervention, and client JavaScript for the raw-process stream only. Its channel, onboarding and separate raw-process-page decisions are amended by [ADR-0005](0005-web-entry-and-local-sessions.md) (implemented). Its phase-one omission of direct worker chat is narrowed by [ADR-0011](0011-direct-worker-chat-from-session-view.md) (implemented) for the case of a session view the owner already has open.

Context: the web is where the owner wants to talk to the agent day to day — read replies, answer questions, make decisions. The prototype in [`docs/design/web-workspace/`](../design/web-workspace/) settled the shape; this records the decisions behind its implementation. In the merged design the workspace sits on the owner API's local channel (ADR-0003): the workspace and `GET /api/messages` are two views of one conversation, not two channels.

## Decisions

1. **The web is the same conversation, not a second one.** The workspace draws one continuous conversation: what the owner said (`sh_inbound`, now keeping its text) and what Sig said (`sh_outbound` on the local channel). Threads focus it and route the next message; selecting one never starts another conversation. "Needs you" is a view onto cards in that conversation (questions, PR consent, offline dispatch, routine offers, memory suggestions), not an inbox.
2. **One local channel, every surface.** A run started from the workspace and one started through the API land in the same outbound rows; a card tapped on the web is answered through the same handlers an API action reaches (a card's outbound row, not the browser, decides what a button means). Credentials (login links, pairing commands) are delivered but marked `private` and never listed in the conversation.
3. **Mutations are idempotent and CSRF-safe.** Every owner action carries a client request id (`sh_web_request`; the run is `user:web:<id>`): a retry is one effect, a different payload under the same id is refused. Requests need the session cookie, a CSRF token header, a same-origin `Origin` and a JSON body.
4. **Static files, no frontend build.** The page is plain HTML/CSS/ES modules in `apps/steward/ui`, shipped with the Worker as static assets (`assets` in the root `wrangler.jsonc`, `run_worker_first` so `/app/assets/*` stays behind the same session check). Rejected: embedding the files as strings in TypeScript (escaping, a generated artifact to keep in sync) and a frontend framework or bundler (a toolchain to own for one owner-facing page). The page's CSP forbids inline script and style and every other origin, and all DOM is built from text nodes — nothing an agent or repository writes is ever parsed as HTML.
5. **Live by nudge, words by stream.** Any ledger write tells connected workspaces (`?role=web&view=workspace` sockets) to refetch the snapshot; losing a nudge costs a minute at most (the page also refetches on a timer and on reconnect). The words of a reply being written follow over pi's agent-event stream, isolated in `workspace-stream.ts` because that API is experimental and pinned: it is held only while a workspace is connected, re-established on the next nudge after the Durable Object wakes, and if it fails the reply still appears — whole — a moment later.
6. **English by default, the choice is the owner's.** The interface starts in English and remembers an explicit EN/中文 choice (`pip.locale` (a stable browser-storage key from the Pip era; kept so an existing choice survives)). Only the interface is translated; user and agent content is shown as written.

## Consequences

- The thread list and timeline pages of ADR-0001 are replaced by the workspace; their URLs (`/app`, `/app/threads/:id`, the card links) open it. `/app/machines` (revoke) and the raw-process page stay server-rendered.
- **Known limit:** text the system itself generates — report and question cards, timeline lines, failure explanations, the machines and raw-process pages — is written in Chinese by the existing templates. The workspace labels what it can (card kinds, the standard buttons, states) and shows the rest as written. Localising those templates needs the owner's language on the server side; recommended as the next step.
- Phase one omits memory management, routine management and direct worker chat; stopping a worker is still asked of Pip in conversation. (An open session view's mechanical control — send/interrupt/resume/stop — is carved out by [ADR-0011](0011-direct-worker-chat-from-session-view.md); routine and memory management, and anything needing Sig's judgment, remain through conversation.)
