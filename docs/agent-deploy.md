# Agent deploy runbook

You are a coding agent on the owner's machine. This runbook turns a fresh Cloudflare account into a running Sig — deployed, initialized, its first machine paired, and the workspace open. Follow it top to bottom, verify each numbered step before moving on, and report each step in one line as you complete it. Anything unexpected: surface it, don't improvise around it.

Decisions behind the flow: [ADR-0003](adr/0003-owner-api-replaces-chat-channel.md) (the owner API and its `SERVER_KEY` — what you initialize), [ADR-0007](adr/0007-agent-driven-deploy.md) (this channel).

## Discipline (read first, applies throughout)

- **Secrets never transit you.** No API key, token or password may appear in your context, your tool arguments, or output you echo — a key pasted into the chat is already leaked into a session transcript and a third-party model provider. `SERVER_KEY` is generated by a command whose output you pipe straight into wrangler and hand to the owner out of band; the model key's channel is the workspace's Settings page or a command the owner runs in their own terminal.
- **Destruction and spending are the owner's calls.** Never delete a Worker, secret, or DNS record without an explicit go-ahead — a Worker deletion destroys the deployment's data. The Wrangler OAuth consent is the owner's click; automate nothing around it.
- You deploy onto **the machine you are running on** — it becomes Sig's first machine. If that is wrong (the owner wants Sig elsewhere), stop and say so before step 2.

## 0 · Preconditions

- Node ≥ 22.18 (`node -v`), npm, git.
- A Cloudflare account (the free plan runs a personal Sig at $0 — see [costs](deploy.md#costs)). None yet? Stop; the owner creates one, then continue.
- A proxy network? Export `HTTPS_PROXY`/`HTTP_PROXY` before every wrangler and curl step. Mainland China additionally blocks `*.workers.dev` outright — if step 3's probe cannot reach the workers.dev address, do [Appendix A](#appendix-a--custom-domain) before step 4.

## 1 · Cloudflare authorization — the owner's click

```sh
npx wrangler login
```

A browser opens; the owner signs in with the account that will own the deployment and clicks **Allow**. Verify with `npx wrangler whoami`.

## 2 · Deploy under a unique name

workers.dev addresses are global across all Cloudflare accounts, so the repository default (`shepherd-steward`) is very likely taken. Pick `sig-<two random words or 4 hex chars>`; if the deploy rejects the name, pick another.

```sh
git clone https://github.com/iefnaf/shepherd && cd shepherd
pnpm install
npm run deploy -- --name <name>
```

The script deploys the Worker and wrangler prints the URL — `https://<name>.<subdomain>.workers.dev`. Read it from the output; every later step uses it.

## 3 · Initialize the secrets

Generate `SERVER_KEY` and set it without ever printing it (ADR-0003: whoever holds it is the owner — so hand it to the owner out of band, e.g. into their password manager, and keep going):

```sh
KEY=$(openssl rand -hex 32)
printf %s "$KEY" | npx wrangler secret put SERVER_KEY --name <name>
npx wrangler deploy --name <name>   # evict isolates pinning the pre-secret state
# Then, out of band, give $KEY to the owner (their terminal, password manager — not the chat).
```

`MODEL_KEY` is optional here — the owner can paste the model key into the workspace's Settings at step 6 instead, which is the preferred channel.

Verify the gates (both against the printed URL; the second uses the key):

```sh
curl -o /dev/null -sW '%{http_code}\n' https://<url>/app                                   # 401 — needs sign-in
curl -o /dev/null -sW '%{http_code}\n' https://<url>/api/messages                          # 401 — no bearer
curl -s -X POST https://<url>/api/messages -H "Authorization: Bearer $KEY" \
     -H 'content-type: application/json' -d '{"text":"ping"}' | head -c 200                # 200 {"id":…}
```

Anything else (timeouts from this machine) → [Appendix A](#appendix-a--custom-domain) for a custom domain, then re-run this step against the new hostname before continuing.

## 4 · Pair this machine

```sh
curl -s -X POST https://<url>/api/pairing -H "Authorization: Bearer $KEY"
# → {"code":"AB12CD34","command":"npx @iefnaf/sig connect https://<url> AB12CD34"} — run it:
npx @iefnaf/sig connect https://<url> AB12CD34
```

The connect command redeems the one-time code, pairs this machine as the deployment's first (installing the background service — launchd on macOS, systemd on Linux). If the code is refused, mint a fresh one — codes are single-use and expire in 10 minutes.

## 5 · Open the workspace

Mint a one-time login link and open it in the owner's default browser (`open` / `xdg-open`). There is no password and no form — the session cookie lands and the workspace appears, showing a "configure a model key" notice. That notice is the owner's next and only input.

```sh
curl -s -X POST https://<url>/api/login-link -H "Authorization: Bearer $KEY"
# → {"url":"https://<url>/link/wl1.home.…"} — single use, 15 minutes
```

## 6 · Model key — the owner's hands only

Ask the owner for a model provider API key (default provider DeepSeek: [platform.deepseek.com](https://platform.deepseek.com) → API Keys). **The owner pastes it into the workspace**: Settings (the avatar, top right). If the owner offers the key in the chat, decline and point back at the Settings page — a rejected key is diagnosed there with a clear notice, too. Terminal-only alternative the owner runs in their own shell, never through you:

```sh
printf %s 'sk-…' | npx wrangler secret put MODEL_KEY --name <name>
```

## 7 · First message

The owner sends a message ("hi") in the workspace and Sig answers. Done. Point the owner at [docs/deploy.md](deploy.md) for everything operational — costs, model provider, secret rotation, updates — and at `POST /api/login-link` (with their SERVER_KEY) to sign in a phone or second browser.

## Appendix A · Custom domain

Needed when workers.dev is unreachable (mainland China) or the owner wants their own hostname. Requires a domain whose DNS is hosted on the same Cloudflare account (free plan enough).

1. List the account's zones (`npx wrangler` auth token → `GET https://api.cloudflare.com/client/v4/zones`), agree with the owner on a hostname (`sig.example.com`).
2. Attach it — dashboard: Workers & Pages → the Worker → Settings → Domains & Routes → Add → Custom domain; or the API: `PUT /accounts/{account_id}/workers/domains` with `{hostname, zone_id, service, environment:"production"}`.
3. Re-run step 3's verification against the new hostname, then redo step 4's `sig connect` **with the final URL** — machines dial the address they were given.
4. Optional: disable the workers.dev route (Worker settings, or `"workers_dev": false`) — the deployment answers nothing owner-facing there anyway.

## Failure playbook

- **Deploy fails on the name** (already taken) — pick another name, retry step 2.
- **`/api/messages` answers 401 with the key set** — a resident Durable Object isolate pins old secrets for minutes after a `secret put`; redeploy once (`npx wrangler deploy --name <name>`), or wait a minute, then re-verify. This is expected platform behavior, not a wrong key.
- **A just-deployed fix "isn't live", or `/app` behaves like an older version** — resident isolate again; same remedy.
- **Sig answers "模型服务拒绝了这个 API key"** — the pasted key is invalid or expired; the owner re-pastes in Settings. The provider's exact error is recorded in the channel log as `model_call_error`.
- **Sig answers "还没有配置模型 key"** — step 6 hasn't happened; the workspace's notice carries an Add-key button.
- **wrangler fails to reach Cloudflare from mainland China** — set `HTTPS_PROXY`; `wrangler tail` needs it explicitly. A proxy that blocks the deployment's hostname: `curl --noproxy '*'` for verification steps.
- **The connector reconnect-loops after a redeploy** — resident isolate again; its retry loop self-heals within a minute. Minutes of looping, then check `sig status` and `sig logs`.
- **SERVER_KEY lost** — the owner cannot be re-derived: mint a new key with step 3's commands (the old one keeps working through a `SERVER_KEY_PREVIOUS` window if you set it; see [deploy.md](deploy.md#secrets-and-rotation)), and re-pair machines that miss the window.
