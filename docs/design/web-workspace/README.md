# Pip · Web 工作台交互草图

> **已落地。** 这份草图确认的布局与交互已按 [ADR-0002](../../adr/0002-pip-web-workspace.md) 实现为真实页面，位于 [`apps/steward/ui`](../../../apps/steward/ui)，接真实数据、实时更新并带测试。本目录保留为设计参考：样例数据、模拟回复与「Demo」标记只存在于这里。

名称与 logo 已确定为 **Pip**。布局与交互仍为设计讨论稿，所有数据与操作结果均为本地模拟。

打开 `index.html` 即可运行，不需要安装依赖或连接服务。刷新页面或点击左下角「Reset demo / 重置示例」可还原数据，语言偏好保留。

## 当前设计假设

- Web 承担日常对话、查看进展和做决定；飞书承接需要用户处理的提醒。
- 左侧按「待处理 / 运行中 / 空闲」组织事项。界面用「事项」称呼 Thread。
- 中间始终与 Pip 对话。默认展示全部对话；选择事项后聚焦相关消息，同时明确下一条消息的关联范围。
- 输入框范围可以切换。草稿按事项保留；切换范围时不会默默把已有草稿交给另一件事。
- 右侧默认显示待处理汇总与概览；选择事项后显示摘要、Agent、分支和时间线。
- PR 确认、离线安排等决定保留在对话中，汇总入口定位到原卡片。处理后同步更新角标与列表。
- 窄屏将右侧变为抽屉，手机端以「对话 / 事项 / 机器」切换。

## 文案与语言

- 默认使用英文，不跟随系统语言。右上角提供 `EN / 中文` 切换，手机端也保留。
- 语言偏好保存在当前浏览器的 `pip.locale`。存储不可用时仍能在当前页面切换。
- 标题和按钮使用短文案，例如「Workspace / 工作台」「Needs you / 待处理」。对话标题为 Pip，输入提示为「Message Pip… / 发消息给 Pip…」。
- `i18n.js` 集中维护 UI 文案；`fixtures.js` 提供双语示例数据。实际输入的消息与草稿保持原文，不随界面语言翻译。
- 切换语言保留当前事项、筛选、草稿、消息、确认状态、展开的处理过程与阅读位置。Logo 展示页也提供语言切换。
- 右侧概览保留待处理、运行中与动态；确认、换机器和停止操作会更新动态。顶部已有的机器和费用统计不在概览中重复。
- 补充搜索空状态、待处理清空状态、未启动会话的禁用入口，以及停止执行的确认。

## Pip 的视觉标识

打开 `brand.html` 查看 logo、反白版本、小尺寸应用和下载入口。

图形由圆润的小写 p 与两个留白的眼睛组成；字标使用小写 `pip`，日常文字中使用 `Pip`。主色为 Forest `#37624D`，配色为 Cream `#F7F6EE` 与 Sage `#EAF0E9`。

`assets/` 中包含：

- `pip-mark.svg` / `pip-mark-light.svg`：透明背景的绿色、米白色图形。
- `pip-wordmark.svg` / `pip-logo.svg`：独立字标与横向组合，均为矢量路径，无字体依赖。
- `pip-icon.svg`：圆角应用图标，用于浏览器标签。
- `pip-mark.png` / `pip-logo.png`：1024 px 图形与 1224 px 横向组合，保留透明背景。`pip-logo-preview.png` 为米白背景的展示图。
- `pip-icon-1024.png`、`favicon-32.png`、`apple-touch-icon.png`：1024、32、180 px 的图标导出。

SVG 是可编辑源文件，PNG 是对应的导出。页面顶部、对话头像、在线状态和浏览器图标已使用同一套资产。

## 可试的交互

1. 点击左侧事项，观察对话、详情和输入框范围的变化；点「全部对话」返回。
2. 在不同事项里输入草稿，切换后返回检查保留情况。
3. 从「待处理」进入卡片，选择创建 PR、暂不创建、等待上线或换机器。
4. 打开机器详情、原始过程与 Pip 处理过程。
5. 对运行中的 Agent 点击停止，确认后查看状态变化。
6. 给 Pip 发送消息；模拟回复期间可以继续输入，观察排队提示。
7. 搜索事项，或使用 ⌘/Ctrl K 聚焦搜索框。
8. 输入草稿或处理卡片后切换语言，检查状态保留；刷新页面检查语言偏好。

## 待讨论

- 选择事项是否同时聚焦中间对话，还是仅更新右侧详情？当前草图采用前者。
- 常用屏幕宽度下，右侧详情应默认展开还是收起？
- 记忆管理是否进入第一阶段？草图尚未包含该页面。
- Web 与飞书的消息分工需要随正式规格一起确认。

## 范围与限制

这份草图仅验证布局、信息层次和交互。它没有真实登录、实时事件流、消息持久化、全文搜索或生产 API；发送消息返回固定演示文本，PR 等操作仅改变内存中的示例状态。机器能力与原始过程内容也都是示例。

本轮没有修改 spec 或 ADR；正式实现需要确认 Web 工作台定位及交互，再更新对应文档。

在 Herdr 中预览时，仓库位于隐藏的 `.herdr` 目录，不能直接作为本地网页开放。将本目录的 HTML、CSS、JS 和 `assets/` 目录复制到专用的非隐藏临时目录，再用 `Herdr browser open` 打开。修改后同步文件并 reload 即可。
